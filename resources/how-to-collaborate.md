## Before You Start — You Need Two Things

- [ ] A GitHub account (free at https://github.com)

## Method 1 — Edit a File Directly (Easiest — Start Here)

This is how you'll add your name to the `OmegaOdysseySquad.md` file.

### Step 1 — Open the repository

Click the repo link your host shared. You'll land on the main page of the project.

> It looks like a folder of files. You'll see `README.md`, `OmegaOdysseySquad.md`,
> and other files listed. This is your team's shared workspace.

---

### Step 2 — Open the file you want to edit

Click on `OmegaOdysseySquad.md` to open it.

You'll see the file displayed nicely — with the table, headings, and text.

---

### Step 3 — Click the pencil icon ✏️

Look for the pencil icon in the top-right corner of the file content area.

```
[ Raw ]  [ ✏️ Edit ]
```

Click it. The file will open in edit mode — like a simple text editor right in your browser.

> 💡 If you don't see the pencil icon, you may need to be added as a collaborator.
> Message your host and ask them to invite you — they'll send you an email from GitHub.

---

### Step 4 — Find your row in the table

Scroll down to the table that looks like this:

```
| Name | Career Background | One Thing I Want to Learn | My GitHub Profile |
|------|------------------|--------------------------|-------------------|
| *(your name here)* | *(your field)* | *(your goal)* | *(your github.com/username)* |
```

Click at the end of the last row and press **Enter** to start a new line.

---

### Step 5 — Add your row

Type your information in this format — keep the pipe `|` symbols, they create the table:

```
| Priya Sharma | Project Management | How to use GitHub Issues as a task board | github.com/priya-sharma |
```

Replace the example with your own details. Don't worry about making it perfect!

> 💡 **Tip:** Your GitHub profile link is always `github.com/` followed by your username.
> Example: if your username is `meera-comeback`, your link is `github.com/meera-comeback`

---

### Step 6 — Scroll down and commit your changes

Scroll all the way to the bottom of the page. You'll see a section called **"Commit changes"**.

You'll see two fields:

**First field** — a short message describing your change.
Replace the default text with something like:
```
Add Priya Sharma to OmegaOdysseySquad
```

**Second field** — optional longer description. You can leave this blank.

Then click the green button: **"Commit changes"**

---

### Step 7 — You did it! 🎉

You've just made your first GitHub contribution.

Go back to the file — you'll see your name in the table. Click on "History" or "X commits" at the top of the file to see your commit in the list. Your name and your message are there, permanently.

**Welcome to GitHub.** 🌸

## Method 2 — Open an Issue (Even Simpler — Great First Step)

If you're not ready to edit a file yet, opening an Issue is a brilliant first action.
An Issue is like leaving a note or a task inside the project.

### Steps:

1. Go to the repository
2. Click the **"Issues"** tab at the top of the page
3. Click the green **"New issue"** button
4. Give it a title — for example: `"Hello from Fatima — joining the squad!"`
5. In the description box, write a short introduction:
   ```
   Hi everyone! I'm Fatima, I work in logistics and supply chain.
   I'm excited to learn GitHub and build my portfolio.
   Looking forward to learning with you all!
   ```
6. Click **"Submit new issue"**

That's it. You've started a conversation inside GitHub. Your host and squad members can reply directly in the Issue thread.

## Method 3 — Fork and Pull Request (The "Real" GitHub Workflow)

This is how most collaboration on GitHub actually works in professional settings.
Try this once you're comfortable with Methods 1 and 2.

### The concept in plain English:

1. **Fork** — make your own personal copy of the shared repo
2. **Edit** — make your changes in YOUR copy (no risk to the original)
3. **Pull Request** — send a message saying "I made some changes — can you review and add them?"
4. **Merge** — the repo owner approves, and your changes become part of the main project

### Step by step:

**Step 1 — Fork the repository**

On the main page of the repo, click the **"Fork"** button in the top-right corner.

GitHub will create a copy of the entire repo in your own account.
You'll be taken to your copy — notice the address bar now shows YOUR username, not the host's.

---

**Step 2 — Edit the file in your fork**

Navigate to `OmegaOdysseySquad.md` in your forked copy.
Click the pencil ✏️ and make your changes exactly as in Method 1.
Commit your changes.

---

**Step 3 — Open a Pull Request**

After committing, GitHub will show a banner saying:

```
This branch is 1 commit ahead of the original repo.
[ Compare & pull request ]
```

Click **"Compare & pull request"**.

You'll see a form. Add a short title and description:

```
Title: Add [your name] to OmegaOdysseySquad
Description: Adding myself to the squad table and first contributions list.
```

Click **"Create pull request"**.

---

**Step 4 — Wait for approval**

Your host will receive a notification. They'll review your change and click **"Merge pull request"** to add it to the main project.

You'll get a notification when it's merged. Your contribution is now officially part of the team repo! 🎉

## Common Questions

**"I can't see the pencil icon — what do I do?"**
You need to be added as a collaborator. Message your host with your GitHub username and ask them to send you an invite. You'll receive an email from GitHub — accept it and you're in.

**"I made a mistake in my edit — can I fix it?"**
Yes! Just open the file again, click the pencil, make the correction, and commit again. GitHub saves every version, so nothing is ever truly broken.

**"I committed something and now I'm not sure it looks right."**
Go back to the file and look at the Preview. If something looks off, open it again with the pencil and fix it. Every commit is a new save — you're not overwriting anything permanently.

**"I'm scared I'll break something."**
You won't. GitHub is designed so that no single person can accidentally destroy a project. Your changes only affect what you edit. And every single version is always recoverable from the commit history.

**"What is a commit message supposed to say?"**
Short and specific. Describe what you actually changed.
- Good: `"Add Meera to squad table"`
- Good: `"Fix typo in my name"`
- Fine: `"Update OmegaOdysseySquad.md"`
- Avoid: `"changes"` or `"edit"` (too vague)
