# 🗺️ GitHub Overview — What to Learn First

> This is your starting point. Not an overload — just the essentials.
> Read this before exploring anything else. It tells you what GitHub is,
> what its key features are, and what to focus on first.

---

## The Big Picture — Git vs GitHub

Before anything else, know that **Git** and **GitHub** are two different things:

| | What it is | Think of it as |
|--|-----------|----------------|
| **Git** | A system that tracks every change you make to files | "Track Changes" in Word — but for any file, forever |
| **GitHub** | A website that hosts your Git projects online | Google Drive + LinkedIn + a project management tool, combined |

> You don't need to understand Git deeply to use GitHub. Everything in your first weeks can be done entirely in the browser — no installation, no commands.

## The 5 Things to Learn First

These are the only concepts that matter in your first session. Everything else can wait.

---

### 1. Repository (Repo)
**What it is:** Your project folder — but it lives online, has a web address, and tracks every change forever.

**Real example:**
> Priya creates a repo called `project-management-templates`. Instantly it has a URL: `github.com/priya/project-management-templates`. She can share this link with any employer.

**Why it matters:** This is the foundation of everything on GitHub. All other features live inside a repo.

---

### 2. README
**What it is:** The front page of your repository. A file called `README.md` that GitHub automatically displays when anyone visits your project.

**Real example:**
```
# Anita's Teaching Resources
Lesson plans, worksheets, and revision guides for secondary school science.

## Subjects covered
- Biology (Years 7–11)
- Chemistry (Years 9–11)

Created by Anita Sharma | Updated April 2025
```

**Why it matters:** A good README makes any project look professional and purposeful. Every repo should have one.

---

### 3. Commit
**What it is:** The act of saving your work to GitHub, with a short note describing what you changed.

Every commit creates a permanent snapshot of your files. You can look back through every commit and see the full history of your project.

**Real example commit messages:**
- `"Add supplier onboarding checklist"`
- `"Update budget template for FY2025"`
- `"Fix typo in sales script introduction"`

**Why it matters:** Your work is never lost. Every version is saved. You can always go back.

---

### 4. Branch
**What it is:** A separate, safe copy of your project where you can experiment without affecting your main work.

**Real example:**
> Maya wants to try a new layout for her status report template, but isn't sure it will work. She creates a branch called `new-layout`, makes her changes there. If she likes it, she merges it back. If not, she deletes it. The main version was never touched.

**Why it matters in session:** Just understand the concept. You don't need to use branches on day one — but knowing they exist removes fear of "breaking something."

---

### 5. Profile Page
**What it is:** Your public face on GitHub. Like a LinkedIn page, but for your projects and work.

A strong profile has:
- A professional photo
- A short bio (one sentence: who you are, what you do)
- Your location and a link to LinkedIn
- Pinned repositories showing your best work
- A profile README — a mini "About Me" that appears on your homepage

**Why it matters:** Employers look at GitHub profiles. A well-built profile with even 2–3 good repos tells a story about your skills and initiative.

## GitHub Issues — Your Built-in Task List

**What it is:** A to-do list and discussion thread that lives inside any repository.

Create an Issue for anything you want to track, fix, or remember about your project.

**Examples by career track:**

| Career | Example Issue |
|--------|--------------|
| Teaching | `"Add Year 9 chemistry worksheet"` |
| Finance | `"Update Q3 budget template"` |
| Project Management | `"Create RACI matrix template"` |
| Sales | `"Add cold email sequence to playbook"` |
| Logistics | `"Document new supplier intake process"` |

**Doc to read:** https://docs.github.com/en/issues/tracking-your-work-with-issues/about-issues

---

## GitHub Projects — A Kanban Board Inside GitHub

**What it is:** A built-in project management board — similar to Trello or Notion. Lives inside your GitHub account and connects directly to your repos.

**Three views:**
- **Board view** — Kanban columns (To Do → In Progress → Done)
- **Table view** — Spreadsheet-style rows and columns
- **Roadmap view** — Timeline for planning ahead

**What you can do with it:**
- Create tasks and move them between stages
- Add custom fields (priority, due date, status)
- Link tasks directly to Issues in your repo
- Collaborate with others in real time

**Real example for a non-developer:**
> Fatima is planning a warehouse process improvement project. She creates a GitHub Project with three columns: `Not Started`, `In Progress`, `Done`. She adds cards for each process she wants to document. As she writes each one, she moves the card forward. At any moment she can see exactly what's complete and what's left.

**Why it matters:** GitHub Projects proves that GitHub is not just for developers. It's a full project management platform that any professional can use.

**Doc to read:** https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects

---

## GitHub Pages — Your Free Website

**What it is:** A feature that turns any repository into a live website — for free.

Your website address will be: `https://yourusername.github.io`

**What people use it for:**
- A personal portfolio website
- A teaching resource hub
- A project showcase
- A simple CV / resume site

**How easy is it?** Three clicks in your repository settings. No coding required for a basic site.

**Doc to read:** https://docs.github.com/en/pages/quickstart

## GitHub Skills — Your Free Self-Learning Path

**What it is:** Official, free, interactive courses built by GitHub. You learn inside real GitHub repositories — not in a simulation.

**Website:** https://skills.github.com

### Recommended order for beginners:

| Course | What you learn | Time |
|--------|---------------|------|
| **Introduction to GitHub** | Repos, branches, commits, pull requests | ~1 hour |
| **Communicate using Markdown** | Format your README beautifully | ~1 hour |
| **GitHub Pages** | Build your free website | ~1 hour |
| **Review pull requests** | Collaborate and review others' work | ~1 hour |

> Each course is self-paced. You learn by doing — real tasks, real feedback, inside your own GitHub account.

## Things You Will Hear About (But Don't Need Yet)

These are real GitHub features — but not for your first few weeks. Just know they exist.

| Feature | What it is | When you'll need it |
|---------|-----------|---------------------|
| **Pull Request** | A formal request to review and merge changes | When working with others on the same project |
| **Fork** | Copy someone else's project to your account | When you want to build on an existing project |
| **Clone** | Download a repo to your computer | When you want to work offline |
| **GitHub Copilot** | AI coding assistant built into GitHub | When you start learning to code |
| **GitHub Actions** | Automated workflows | Much later — advanced use |
| **Terminal / CLI** | Using Git via typed commands | Optional — everything can be done in the browser |
